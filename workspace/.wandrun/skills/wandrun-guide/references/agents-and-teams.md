# Agent、提示词与团队

App 基线：0.2.0；提交 `3226bed53ef73a60fc13d02fb440693979078077`；核对日期 2026-11-05。

## 新建 / 编辑的最短路径

1. 聊天左上菜单打开对话抽屉，点 **Agent**，再点列表右上 **＋**。零 Agent 时也可点“新建 Agent / New agent”。没有模板选择页。
2. 填“名字 / Name”“说明 / Description”，点“提示词 / Instructions”输入职责文本，再点“完成 / Done”回主表单。
3. 按需选择模型与能力；最后在主表单右上点“创建 / Create”。创建成功回上一页，不自动开聊天；回新对话页选择它开始使用。

已有项：抽屉 › Agent › 点该 Agent › 资料页右上铅笔（编辑 Agent / Edit agent）。也可列表左滑该行，再点铅笔。主表单右上“保存 / Save”提交；已有项从整个表单返回也会尝试自动保存。子面板“完成 / Done”或返回只保留草稿，不单独保存。新建有内容时返回会让用户放弃或继续编辑，不自动创建。

没有 Agent 配置管理工具。不能改 `.wandrun/agents.toml`、找令牌或自行调用网关 HTTP 来代用户创建 / 编辑。可以提供可粘贴的名字、说明和提示词；不把文本草稿说成已经安装好的 Agent。

## 字段含义（按用户当前问题取舍，不一次抄全表）

| 中文 / English | 作用与边界 |
|---|---|
| 名字 / Name | 用户看到的名称，去首尾空白后非空、单行、最多 64 字符；不区分大小写唯一，不是技术 id |
| 说明 / Description | 列表和协作目录中的简短职责说明；必填，不等于完整行为指令 |
| 提示词 / Instructions | 持续的角色职责、做事方式、交付与边界；必填。面板“完成”之后仍需主表单创建 / 保存；修改下一轮生效 |
| 模型 / Model | 可用模型来自服务器当前目录；目录不可用时不要编一个可选型号 |
| 推理强度 / Reasoning effort | 所选模型支持的档位，界面以实际目录展示；更高不是所有任务都更好 |
| Fast | 请求优先处理，可能多耗订阅额度；独立于推理强度，不是“降低思考”或必然更快的承诺 |
| 执行环境 / Execution environment | Local 或已有 Instabox，决定文件、命令和浏览器在哪里运行；空闲时可切，旧文件不自动迁移 |
| 代码模式 / Code mode | 用脚本批量调用本 Agent 已有工具、处理文件，只向模型返回结果；不授予其他 Agent 的工具或额外权限 |
| 技能 / Skills | 勾选给该 Agent 用的操作说明 / 资源包。导入与勾选是两步，新 Agent 不自动带默认助手技能 |
| 连接器 / Connectors | 为该 Agent 勾选已配置的 MCP 工具；可直接携带或按需搜索，两者同服务互斥。连接成功也不会自动授权所有 Agent |
| 团队成员 / Team members | 选择可直接委派的其他 Agent；不包含自己，也不自动替它们配置模型或能力 |
| 系统能力 / System capabilities | 已保存 Agent 配置的只读能力列表，不是新的权限开关，新建表单没有这个入口 |

## 帮用户写好提示词

先从其明确目标提取：职责与不做什么、常见输入、希望的成果 / 证据、什么时候需人决定。缺少真正影响结果的偏好才问；旅行任务不必为建 Agent 先索取护照 / 身份证等信息。用少量具体约定代替“你是世界顶尖专家”“永远完成所有事”。工具必须在 App 真正勾选，不能靠提示词许愿获得。

提示词不必复制 messages / next、附件协议、完整富交互组件表、全部记忆规则或 browser CLI；运行时与技能负责这些。

例如用户要旅行规划助手，可给下列可直接粘贴草稿，并明确它尚未创建：

```text
你是旅行规划助手，帮助用户把旅行目标变成可实行的行程。
先使用已有的目的地、日期、预算与同行限制；只有缺失信息会显著改变方案时才简短询问。
建议行程时兼顾地理顺路、交通耗时、营业时间、预算与休息；信息不确定时注明，票价、签证和开放时间优先核对官方来源并附链接。
给出每天的重点安排、必要预约与备选，不为了填满时间制造景点。不虚构预订或实时价格。
你可以检索和准备方案；付款、登录与需要本人完成的步骤交给用户。不能把计划草稿说成已预订。
按用户语言交流，先给可用结论，再解释关键取舍；用户调整后只更新受影响部分。
```

对应说明可写“根据日期、预算与偏好规划可执行的旅行行程，核对交通和开放信息。”。在其需要查网页时提示勾选 browser / 合适连接器；不假定新 Agent 自动有 Exa。建立后用一个真实小任务试，再针对具体偏差修改提示词，不为想象中的所有问题塞入一大页规则。

只有确实反复出现同类任务时，才建议用户建专门 Agent，并主动起草；单次任务直接完成，不每次推广建 Agent。

## 加成员与委派

默认 `wandrun` 没有成员；只有一个 Agent 时“团队成员”没有其他候选，需要用户先创建另一个。

路径：抽屉 › Agent › 需要委派的入口 Agent › 右上铅笔 › 能力（Capabilities 分组）› 团队成员（Team members）› 勾选已有 Agent › 完成（Done）› 主表单保存（Save）。不是到“成员 / Members”资料标签添加；那个标签只读。

- 加成员是“允许入口 Agent 向它创建协作任务”，不是复制技能、共享完整历史、群聊或每条消息强制群发。成员按自己的模型、技能、连接器和执行环境运行；默认没有成员时不要假装已委派。
- 例子：用户先创建“资料研究员”并配置其检索能力，再把它加入入口助手的团队。用户在入口对话交办“让资料研究员调查这件事，再帮我整理结论”，入口可给成员必要上下文并整合结果。
- 聊天顶部名称旁的数量按钮打开协作卡片；点某个子对话查看其任务，用户可直接插话，左上返回主对话。点名字本身只打开资料。
- 资料页“成员 / Members”点一行进入与该成员的聊天，不等于创建一项由当前入口发起的委派。
- 停止上级任务可能同时停止其子分支；别承诺所有成员必定继续。运行结果与可委派范围以当前运行时目录为准，不能拿手册中的示例人名当真实成员。

删除在 Agent 编辑页底部“删除 Agent / Delete agent”，有成员引用或工作中时可能被拒绝。确认会永久删除它的对话、定时和工作记忆；共享用户画像、其他团队成员与对话文件保留。不要自动建议用户删除默认助手以开始使用。
